# GREEN-API · MAX Message UI

Веб-интерфейс в стиле мессенджеров Telegram / Max для отправки и получения **текстовых** сообщений мессенджера **MAX** через [GREEN-API](https://green-api.com/max).

Возможности (минимальный набор):

- подключение к инстансу GREEN-API по `apiUrl` + `idInstance` + `apiTokenInstance`
- создание чата по ID получателя, список чатов, непрочитанные
- отправка текста методом [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/)
- приём входящих методом HTTP API: `ReceiveNotification` → `DeleteNotification` (long-poll)
- статусы исходящих: «отправляется» → галочка ✓ / «Не отправлено»

## Установка и запуск

Конфигурации через файлы нет: `.env` не используется, все параметры (`apiUrl`, `idInstance`, `apiTokenInstance`) вводятся в форме подключения и хранятся в localStorage (`green-api-credentials`). Ключи GREEN-API выдаются в личном кабинете (см. секцию ниже).

```bash
nvm use 22          # при необходимости
npm install
npm run dev         # dev-сервер: http://localhost:5173
```

Если порт 5173 занят, Vite возьмёт следующий (5174) — итоговый URL печатается в консоли запуска.

В dev-режиме запросы идут не напрямую в `https://<кластер>.api.green-api.com` (он не отдаёт CORS-заголовки, браузер блокирует и preflight, и чтение ответов), а через same-origin прокси dev-сервера: `/green-api-proxy/<encodeURIComponent(apiUrl)>/waInstance…`. Прокси реализован плагином в `vite.config.ts` и включается автоматически в dev; в тестах адрес остаётся прямым.

Другие команды:

| Команда | Действие |
|---|---|
| `npm run dev` | dev-сервер с HMR (http://localhost:5173) |
| `npm run build` | проверка типов (tsc) + сборка бандла в `dist/` |
| `npm run preview` | локальная раздача собранного бандла (http://localhost:4173) |
| `npm test` | прогон всех тестов (vitest run) |
| `npm run test:watch` | тесты в watch-режиме |
| `npm run lint` | ESLint (код-стайл + границы FSD по AGENTS.md) |
| `npm run lint:fix` | то же с автофиксом |

## Подготовка инстанса GREEN-API (обязательно перед ручным тестированием)

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com). Для MAX доступен бесплатный тариф «Разработчик» (есть квоты на количество сообщений).
2. Создайте инстанс типа **MAX** и привяжите аккаунт MAX по QR-коду (кнопка QR в карточке инстанса; отсканируйте из приложения MAX).
3. Скопируйте из карточки инстанса **три значения**: `apiUrl` (хост кластера, например `https://3100.api.green-api.com` — у каждого инстанса он свой, это НЕ всегда `api.green-api.com`), `idInstance` и `apiTokenInstance`.
4. В настройках инстанса включите переключатель **«Получать уведомления о входящих сообщениях и файлах»** (`incomingWebhook`).
5. Поле **webhookUrl должно быть пустым** — приложение забирает уведомления методом `receiveNotification`. Если URL заполнен, API вернёт ошибку `Message cannot be received because custom webhook url is set`

### Формат chatId в MAX

| Тип чата | Формат | Пример |
|---|---|---|
| Личный чат (ID пользователя MAX) | число | `10000000` |
| Номер телефона | `79991234567@c.us` | `79991234567@c.us` |
| Групповой чат | отрицательное число | `-10000000000000` |

Как узнать chatId собеседника: попросите его написать вам первым — чат и ID появятся в интерфейсе автоматически; либо воспользуйтесь методом [CheckAccount](https://green-api.com/v3/docs/api/service/CheckAccount/) в отладчике API в личном кабинете.

Чтобы писать **самому себе** («Избранное» в MAX): chatId — это ваш собственный ID пользователя MAX (не номер). Проще всего узнать его так: отправьте сообщение на номер, привязанный к инстансу, из своего же аккаунта — чат появится в списке, а его `chatId` виден в шапке (число типа `10000000` в примерах документации — просто образец значения, а не «ID избранного»).

В форме подключения **apiUrl — первое поле**, и оно обязательно: если указать `https://api.green-api.com` вместо хоста кластера инстанса, запросы не пройдут и приложение покажет «Нет соединения с сервером GREEN-API» (оригинальная причина видна в консоли браузера, `console.error`).
